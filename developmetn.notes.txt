Что где лежит

schemas/ — JSON Schema(ы) для метаданных
examples/metadata/ — примеры JSON метаданных (валидный/невалидный)
examples/data/ — (позже) тестовые файлы или заглушки структуры
examples/qc/ — (опционально) примеры FastQC-артефактов
examples/manifest.csv — список файлов для intake
src/ghga_intake/ — код

Поля, которые включаем в mvp

Dataset/Sample-level metadata (sample_001.json):
sample_id — уникальный ID
project_id — проект/когорта
organism — Homo sapiens
data_type — WGS/WES/RNA-seq
platform — Illumina/ONT/PacBio
library_strategy — WGS/WES/RNA-Seq (опционально, но полезно)
consent — controlled/open (мок)
files — список файлов (path/type/md5)

sample_bad.json
- platform неправильный
- path ведёт на отсутствующий файл

Почему schema такая

additionalProperties: false — дисциплина (лишние поля не пролезут)
pattern на sample_id — сразу предотвращает хаос в ID
enum для platform и data_type — предотвращает “UnknownPlatform”
files — массив объектов с path, file_type, optional md5

Мы объединяем результаты из двух источников:

1) Metadata validation
OK / NOT OK
список ошибок по каждому sample

2) File checks (manifest)
OK / NOT OK по каждому файлу
ошибки (missing, empty, md5 mismatch)
warnings (extension mismatch и т.п.)

И собираем это в один структурированный JSON..
{
  "summary": {...},
  "samples": {...},
  "files": [...]
}

Пример report.json
{
  "summary": {
    "total_samples": 2,
    "samples_valid": 1,
    "samples_invalid": 1,
    "total_files": 3,
    "files_ok": 2,

  "samples": {

    }
  ]
}

"I built a small intake prototype that merges metadata validation and 
file integrity checks into a single readiness report,
clearly separating blocking errors from warnings. 
This mirrors how I would support dataset onboarding in GHGA."


Readness score

Metadata: 50 баллов
если все samples валидны → 50
иначе пропорционально valid/total

Files: 40 баллов
пропорционально ok/total

QC presence: 10 баллов
пока у нас QC не реализован → ставим 0 или “N/A”
но в отчёте показываем как “not implemented yet / optional”

И добавим статус:
READY если score ≥ 90 и нет blocking errors
NEEDS_FIX иначе
